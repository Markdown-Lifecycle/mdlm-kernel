# Anchor accepted publications outside their saved copies

Settlement, replay and reads currently authenticate only that a transaction's saved copies agree with each other: `execution.json` and the datum files it lists. A coordinated edit to both is accepted. The audit found six such edits: an output with its datum, `snapshot`, `package.language`, and a registered review's subject, inputs or `verdictSha256` (KF-011, #1104). A digest-only edit of `proposalDigest` is also accepted, because the repository holds no other copy of it (KF-009, #1106). Git history is the only evidence left of the original publication.

**Where the anchor lives.** Inside the publication lock, every accepted publication writes one Git blob: `mdlm-publication-anchor@1`, with the transaction ID and the SHA-256 of each file in the transaction directory (sorted relative path, exact bytes). The kernel points `refs/mdlm/publication/<transaction-id>` at that blob before it moves the staged directory into place, so a published transaction is never left without its anchor. A crash between the two steps leaves only an anchor for a transaction that doesn't exist. Reads ignore it, and a later publication of the same operation replaces it. This follows the existing execution receipts in `refs/mdlm/execution/…`: content-addressed Git objects that the working-tree data files don't contain, and that `git add`/`commit` of `.lifecycle/` don't touch.

**What it covers.** Every byte of every file in `.lifecycle/data/.transactions/<id>/`. That is all of `execution.json` (`proposalDigest`, `snapshot`, `package`, `subject`, `inputs`, `evidence`, `authority` including `review.proposalSha256` and `verdictSha256`) and every published datum file. Every repository read recomputes the digests, and settlement and exact-byte replay go through that read. A read refuses a transaction whose files differ from its anchor, or that has no anchor. Outside the anchored files, nothing changes: review registrations, execution receipts and the package selection keep their current checks.

**What it doesn't protect against.** Anyone who can run `git update-ref` in the lifecycle repository can re-anchor a coordinated edit. The anchor catches edits to saved copies, which is what the audit found: an agent or tool rewriting files. It doesn't stop a deliberate forger with full repository write access. For example, someone who commits a coordinated edit and then deletes every anchor ref leaves evidence only in Git history, as today. Stopping that requires an anchor the author can't write, such as the manager-owned review registry (`MDLM_REVIEW_REGISTRY`). Every read would then depend on external state, and it would be a separate decision.

**How existing repositories migrate.** A repository without anchors keeps reading and settling. The first kernel command that finds no `refs/mdlm/publication/*` at all anchors every existing transaction once, using Git history as the baseline. If a transaction's files are tracked, they must be byte-identical to `HEAD`. Otherwise the migration refuses and names the differing files, because an uncommitted edit to a committed publication is exactly what the anchor exists to catch. A transaction directory that was never committed (a normal state, since the kernel doesn't commit) is anchored as found. After migration, a transaction without an anchor is refused. Deleting every anchor ref only re-runs the migration, which still holds committed transactions to their committed bytes. Moving a repository must carry `refs/mdlm/*` (`git push origin 'refs/mdlm/*:refs/mdlm/*'`), where execution receipts already live. A clone without those refs re-anchors from its committed history. The anchors are written as one atomic ref update.

**Consequences.** This deliberately changes the integrity contract. This kernel currently accepts the six KF-011 edits and the KF-009 digest-only edit, and will refuse them. The kernel-rewrite compatibility decisions (D008, D011, D012) froze those acceptances as observed reference behavior. The rewrite needs the same change separately; they don't constrain this kernel. Every repository read hashes every transaction file and lists the anchor refs once. If a measured slowdown shows up, anchors can be cached by Git blob ID without changing the contract. The operator guide says to carry `refs/mdlm/*` when moving a repository.
